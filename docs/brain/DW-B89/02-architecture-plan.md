## 1. Problem Statement

### Defect DW-B89-01 — OCO ID reuse after in-session recompile

**Observed error** (NT8 OutputTab1):
```
The OCO ID 'PTT-BE-Sim101-245037222-2' cannot be reused.
```

**Root cause**:
`CopyEngine._mstbeOcoSeq` is seeded from `Environment.TickCount` alone
(`private volatile int _mstbeOcoSeq = Environment.TickCount;`). `TickCount` has
millisecond resolution and 32-bit range. The D5 format string (`seq.ToString("D5")`)
allows only 100,000 unique suffix values per account prefix. When NT8 recompiles an
AddOn within a running session, the GC'd `CopyEngine` instance is replaced by a new
one. If the new `TickCount`-based seed falls within the previously-used range — possible
under same-millisecond recompile or after counter wrap — OCO IDs generated by the new
instance collide with IDs still held in NT8 session memory (cancelled orders are retained
for the entire session).

**Impact**: Every OCO pair submission fails silently (bare `catch{}` absorbs the error).
Position is left without stop protection.

---

### Defect DW-B89-02 — BuyToCover StopMarket rejected as below market

**Observed error** (NT8 OutputTab1):
```
Buy stop or buy stop limit orders can't be placed below the market.
```

**Root cause**:
On a short entry with `buf=0t`, `newStop` equals the entry price. Between the BE trigger
and `acc.Submit()`, the market moves adversely (ask rises above `newStop`). NT8 rejects
the BuyToCover StopMarket because the stop price is now below the current ask. The bare
`catch { /* non-fatal */ }` in `PttBreakEvenSwap.Execute()` swallows the rejection
silently. NT8 then auto-cancels the paired Limit Target (its OCO group is now broken).
The position is left naked with no stop and no target.

**Impact** (two parts):
1. Silent rejection: operator cannot diagnose the failure without raw NT8 logs.
2. Naked position: after Target auto-cancel, no bracket order protects the trade.

## 2. Solution Design

### File 1 — `src/PropTraderTools/CopyEngine.cs` (L205)

**Change**: Replace the seed initializer with a XOR formula:

```csharp
// BEFORE (DW-B88):
private volatile int _mstbeOcoSeq = Environment.TickCount;

// AFTER (DW-B89):
private volatile int _mstbeOcoSeq = Math.Abs(
    Environment.TickCount ^ (int)(DateTime.UtcNow.Ticks & 0x7FFFFFFF));
```

**Rationale**:
- `DateTime.UtcNow.Ticks` has 100 ns resolution. The low 31 bits (`& 0x7FFFFFFF`)
  change every ~214 seconds of tick-time but are extremely sensitive to recompile
  timing — a sub-millisecond recompile changes this value by hundreds of thousands.
- XOR with `TickCount` combines two independent entropy sources. Post-recompile, the
  seed is statistically unique vs the previous run's seed even when recompile occurs
  within the same millisecond.
- `Math.Abs` prevents a negative seed value (corner case: `TickCount` negative after
  ~24.9 days of uptime XOR with a small positive DateTime component). `0x7FFFFFFF`
  mask ensures the DateTime component is always non-negative so XOR sign is bounded.
- **JS-023**: `volatile int` access pattern unchanged. `Interlocked.Increment` on
  `NextBeOcoSeq()` unchanged. No lock() added.
- **No structural change** to `NextBeOcoSeq()` signature.

### File 2 — `src/PropTraderTools/Features/PttBreakEvenSwap.cs` (5 changes)

#### Change 1: D5 → D7 format string (line ~84)

```csharp
// BEFORE:
+ "-" + seq.ToString("D5") + "-" + i;

// AFTER:
+ "-" + seq.ToString("D7") + "-" + i;
```

D7 provides 10,000,000 unique suffix values per account prefix, vs 100,000 for D5.
Combined with the high-entropy XOR seed, this makes OCO ID collision probability
negligible for any realistic NT8 session duration.

#### Change 2: Replace all 3 bare catch blocks

All three `catch { /* non-fatal */ }` blocks become:

```csharp
catch (Exception ex)
{
    NinjaTrader.Code.Output.Process(
        "[BE-ERR] " + acc.Name + " submit failed: " + ex.Message,
        NinjaTrader.NinjaScript.PrintTo.OutputTab1);
}
```

Rationale: NT8 order rejection exceptions must be visible to the operator in OutputTab1.
Silent swallowing was the primary reason DW-B89-02 was only discovered in SIM gate, not
in real-time monitoring. **JS-001**: no new `throw`; catch only logs.

#### Change 3: New private static helper `IsStopPriceSubmittable`

Add BEFORE `Execute()`:

```csharp
private static bool IsStopPriceSubmittable(
    Instrument instr, bool isLong, double stopPrice)
{
    if (isLong) return true;               // (1) Sell StopMarket below market is valid
    double ask = instr.MarketData?.Ask?.Price ?? 0.0;
    if (ask == 0.0) return true;           // (2) fail-open: no market data, let NT8 log
    return stopPrice >= ask;               // BuyToCover stop must be >= ask
}
```

**CYC = 2** (branch 1: isLong; branch 2: ask==0). Well within limit of 3.

**NT8 API**: `instr.MarketData?.Ask?.Price` reads the current ask from the NT8 CBI
Instrument. Null-safe access handles no-subscription case. Fail-open (`return true`)
ensures that if market data is unavailable, the Submit proceeds and NT8 logs any
rejection (which is now surfaced by Change 2).

#### Change 4: IsStopPriceSubmittable guard in with-targets for-loop

Wrap the stop submit block with the guard:


**CYC budget note**: The `if (sOrd != null)` guard inside the stop-submit try is
**removed** (replaced by catch). The `if (tOrd != null)` guard inside the target-submit
try is **kept** (limit price=0 would be catastrophic). This exchange maintains
`Execute()` CYC = 8 (see Section 3).

### File 3 — `src/PropTraderTools/Features/PttBreakEven.cs`

**Change 1** (L357 in `BuildBeOcoId`):
```csharp
// BEFORE:
return "PTT-BE-" + prefix + "-" + seq.ToString("D5") + "-" + pairIndex.ToString();

// AFTER:
return "PTT-BE-" + prefix + "-" + seq.ToString("D7") + "-" + pairIndex.ToString();
```

**Change 2** (L10 header comment):
```
// Old formula: "PTT-BE-"+accPrefix+"-"+seq.ToString("D5")+"-"+pairIndex
// New formula: "PTT-BE-"+accPrefix+"-"+seq.ToString("D7")+"-"+pairIndex
```

**Rationale**: `PttBreakEven` uses the same `CopyEngine.Instance.NextBeOcoSeq()` counter
as `PttBreakEvenSwap`. Aligning to D7 ensures both code paths cannot generate the same
OCO ID even if the format differs. Mixed D5/D7 would introduce a collision class where a
D5-generated ID (e.g. "...00001...") matches the 5-char prefix of a D7 ID ("...0000100...").

**Scope**: `BuildBeOcoId` only. `PttGlobalBreakEven.cs` uses prefix `PTT-BEG-*` and its
own independent counter — D5 is intentionally preserved there and is **out of scope**.
