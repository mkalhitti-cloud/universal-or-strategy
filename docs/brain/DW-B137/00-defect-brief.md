# DW-B137 — Defect Brief

**ID**: DW-B137
**Priority**: P1
**Status**: OPEN — needs architect investigation
**Discovered**: 2026-08-31 Director SIM gate session (B129 post-compile test)
**Reported by**: Director live observation
**Related**: DW-B134 (parent — ATM bracket drag), B129 LaneB (partial fix)

---

## Summary

ATM bracket drag on the leader does NOT sync to followers. The DW-B134 fix (B129 LaneB)
targeted the `"Buy STP"` / `"Sell STP"` ATM name format via `EndsWith("STP")`. The Director's
actual ATM template (`MES $200 SL 6`) generates orders named `Stop1`, `Stop2`, `Stop3`,
`Target1`, `Target2`, `Target3` — a different naming format. The `cancel+resubmit` path in
`SyncAtmFollowerBracket` was never reached during the SIM test.

---

## Symptom

Director dragged both the stop loss and target on the leader (Sim101) MES chart.
Follower accounts (Sim102/103/104) did not update their stops or targets.
No bracket-drag log lines appeared in Output Tab.

---

## ATM Template in Use

**Template name**: MES $200 SL 6
**Order names generated by this template**:
- Stop brackets: `Stop1`, `Stop2`, `Stop3`
- Target brackets: `Target1`, `Target2`, `Target3`
- Entry bracket: `Entry`

**NOT** the `"Buy STP"` / `"Sell STP"` format that the DW-B134 fix targeted.

---

## Code Path Analysis (architect must verify)

### Layer 1: IsBracketLegStatic (~L3621 CopyEngine.cs)

Current predicates after DW-B134 fix:
```csharp
// (existing) StartsWith("Stop")        -> matches Stop1, Stop2, Stop3 ✅
// (existing) StartsWith("Target")      -> matches Target1, Target2, Target3 ✅
// (DW-B134 added) EndsWith("STP")      -> matches "Buy STP", "Sell STP" ✅
```

For the MES $200 SL 6 template, `Stop1` matches `StartsWith("Stop")` and `Target1` matches
`StartsWith("Target")`. So Layer 1 SHOULD be passing these names through.

**Question for architect**: Is `IsBracketLegStatic` even being called for these order names?
The drag event must first reach `HandleBracketChange`. Confirm `OnOrderUpdate` routes
drag events with `Stop1`/`Target1` names to `HandleBracketChange`.

### Layer 2: SyncFollowerBracket -> SyncAtmFollowerBracket (~L2048 CopyEngine.cs)

After Layer 1 passes, `SyncFollowerBracket` is called. It should call `SyncAtmFollowerBracket`
for ATM-owned brackets. The routing condition is `IsAtmSTPOrder` (~L2028):
```csharp
// IsAtmSTPOrder: order.Name.EndsWith("STP", StringComparison.OrdinalIgnoreCase)
```

`Stop1` does NOT end with "STP". So `IsAtmSTPOrder` returns FALSE for `Stop1`/`Stop2`/`Stop3`.
This means `SyncFollowerBracket` falls through to the old `acc.Change()` path — which is a
confirmed silent no-op for ATM-owned brackets.

**Root cause**: `IsAtmSTPOrder` (the predicate that routes to `SyncAtmFollowerBracket`)
only matches the `"STP"` suffix format. `Stop1`/`Stop2`/`Stop3` names are not routed to the
cancel+resubmit helper. They fall back to `acc.Change()` which does nothing.

---

## Root Cause (Confirmed)

`IsAtmSTPOrder` predicate (`EndsWith("STP")`) does not cover `Stop1`/`Stop2`/`Stop3` names.
`SyncFollowerBracket` uses `IsAtmSTPOrder` to decide whether to cancel+resubmit.
For the MES $200 SL 6 template, this predicate returns false → `acc.Change()` is called →
silent no-op → follower bracket unchanged.

Similarly for targets: there is no equivalent `IsAtmTargetOrder` predicate to route
`Target1`/`Target2`/`Target3` to a cancel+resubmit path (if targets also need it).

---

## Fix Design (architect must confirm)

**Option A (minimal)**: Extend `IsAtmSTPOrder` to also match `StartsWith("Stop")`:
```csharp
private bool IsAtmSTPOrder(Order o) =>
    o.Name.EndsWith("STP", StringComparison.OrdinalIgnoreCase)
    || o.Name.StartsWith("Stop", StringComparison.OrdinalIgnoreCase);
```
- Covers both "Buy STP" and "Stop1"/"Stop2"/"Stop3" formats
- CYC: 1 → 1 (single expression, no new branches)
- Risk: `StartsWith("Stop")` is broad — confirm no non-ATM orders start with "Stop"
  that should NOT be routed to cancel+resubmit

**Option B (explicit list)**: Match known ATM stop name patterns explicitly:
```csharp
private bool IsAtmSTPOrder(Order o) =>
    o.Name.EndsWith("STP", StringComparison.OrdinalIgnoreCase)      // "Buy STP" format
    || System.Text.RegularExpressions.Regex.IsMatch(o.Name, @"^Stop\d+$"); // "Stop1" format
```
- More precise but introduces Regex allocation (hot path concern)

**Option C (IsBracketLegStatic as gate)**: Since IsBracketLegStatic already passes
`StartsWith("Stop")` names, use its result as the routing signal instead of IsAtmSTPOrder.
Rename/refactor IsAtmSTPOrder to IsAtmOwnedBracket and align with IsBracketLegStatic logic.

**Architect must also check**:
- Do `Target1`/`Target2`/`Target3` drag events need the same cancel+resubmit treatment?
  Or does `acc.Change()` work for ATM target brackets (only stops are unmodifiable)?
- Is `HandleBracketChange` even receiving the drag event for these order names?
  Add a diagnostic log at the entry of HandleBracketChange to confirm.
- NT8_FULL_REFERENCE.md: confirm which order types are ATM-owned and which accept acc.Change()
