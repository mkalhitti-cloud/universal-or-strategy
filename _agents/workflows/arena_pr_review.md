---
description: $Arenaprreview -- Deep Architectural PR Audit via Arena AI
---

Use this workflow to perform a rigorous, adversarial Red Team audit on a GitHub Pull Request using the Arena AI models.

This workflow uses a specialized prompt that forces the Arena models to act as forensic auditors and outputs a highly dense, minimalist Terminal/Report Dashboard. This constrains them from wasting compute on UI aesthetics and focuses all their reasoning tokens on architectural analysis.

---

## Phase 1: Prepare the Arena Prompt

Copy and paste the following prompt template into the Arena AI interface. Be sure to replace the `BUILD_TAG` and `PR_LINK` brackets with the correct information for the current session.

```text
$Arenaprreview

**MISSION**: Deep Architectural PR Audit
**BUILD_TAG**: [Insert Current Build Tag]
**REPO**: V12 Universal OR Strategy
**PR_LINK**: [Insert GitHub PR Link Here]

**ROLE & DIRECTIVE**:
You are operating as the P5 Red Team / Forensic Auditor for the V12 Universal OR Strategy codebase. Your directive is to perform a rigorous, independent architectural audit of the changes in the provided Pull Request link.

**UI INSTRUCTIONS**:
You must output a highly dense, minimalist "Terminal/Report Dashboard" using React/Tailwind. 
- Use a dark theme (e.g., `bg-[#080b0f]`).
- Use monospace fonts (`font-mono`) and extremely small text (`text-[10px]` or `text-xs`) to maximize data density.
- DO NOT waste tokens on animations, glassmorphism, or fancy UI elements.
- The UI must look like a raw, analytical CLI tool.

**AUDIT REQUIREMENTS**:
1. Scan the PR diff for regressions in concurrency, state management, order lifecycle, and compiler safety.
2. Specifically check for violations of the "Permanent DNA": no legacy `lock()` blocks, correct FSM/Actor `Enqueue` usage, and ASCII-only C# strings.
3. Group your findings into three severity levels: 🔴 CRITICAL (P0), 🟡 WARNING (P1), and 🔵 QUALITY (P2).
4. For EVERY finding, you MUST provide:
   - `flaw`: What is wrong.
   - `rootCause`: The architectural or logical reason the flaw exists.
   - `remediation`: How to fix it (be specific with code instructions).
5. Conclude the dashboard with a "Remediation Priority Matrix — Merge Gate Requirements".
```

---

## Phase 2: Run the Audit & Download

1. Submit the prompt to the Arena AI models.
2. Wait for the models to complete their analysis and generate their dashboards.
3. Download the `$battlezip` containing the generated `App.tsx` files.

---

## Phase 3: Synthesize Findings

1. Extract the zip file and analyze the `App.tsx` components.
2. Read the `FINDINGS` arrays generated by the models.
3. Cross-reference the findings with other automated bots (CodeRabbit, Sourcery, etc.).
4. Generate a consolidated `pr_audit_synthesis_report.md` for the Director, highlighting any critical regressions (e.g., dead-letter functions, incorrect account domains, unhandled exceptions) that must be addressed before the PR can be merged.

---

## Phase 4: Mandatory Self-Improvement Audit (NON-NEGOTIABLE)

After EVERY use of this workflow, the executing agent MUST perform a post-use audit:

1. **Did the models ignore the UI constraints?** Refine the UI instructions in the prompt.
2. **Were the findings too superficial?** Add specific architectural constraints to the "AUDIT REQUIREMENTS" section.
3. **Did the prompt trigger content filters?** Document the blocked phrases and provide safe replacements.

**If no gap was found, explicitly state:** `workflow(arena_pr_review): no gaps identified -- workflow correct as written.`

**Commit format:**
`workflow(arena_pr_review): [what was fixed and why]`
